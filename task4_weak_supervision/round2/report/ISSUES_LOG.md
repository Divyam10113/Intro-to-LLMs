### G1-5 check: source `valid/` against every `test/` file

Run 2026-11-22 (`logs/valid_vs_test_check.json`). 2,130 `valid/` images were checked against 27,172 `test/` images.

| Dataset | valid normal / abnormal | Same file name as a test file | Byte-identical to a test file |
|---|---|---|---|
| Brain | 39 / 44 | 10 (abnormal) | **10** (the same 10) |
| Liver | 93 / 73 | 0 | 0 |
| RESC | 45 / 70 | 0 | 0 |
| OCT17 | 16 / 24 | 1 (different image) | **1** under a different name (`valid/good/NORMAL-33350-12.jpeg` = `test/good/NORMAL-33350-2.jpeg`) |
| Chest | 70 / 1,420 | 0 | 0 |
| HIS | 117 / 119 | 131 | 0 (the numbering is reused for different images) |

**Finding:** `valid/` is not fully disjoint from `test/`. **11 validation images** are exact copies of test images: 10 abnormal in Brain and 1 normal in OCT17 (OCT17 then has 15 normal validation images left). Because the sources train on their `test/` folders (B1), those 10 would be validation images the model also trained on. When Brain is the target, `valid/` of Brain is not used at all, so this is not target leakage.
**Proposed fix:** drop from validation every `valid/` image that is byte-identical to any `test/` image of any dataset. The list is written to `splits/valid_excluded.json`, and a test checks it.
