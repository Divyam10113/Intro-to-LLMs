## C. Gap-analysis inputs — `pipeline/gap_inputs/` and `prompted/gap_inputs/`

Both runs carry the same five required inputs, generated by
`build_gap_inputs.py` (repository artifacts + the anchor PDF only; no network,
no LLM — re-run it to regenerate):

| checklist item | file (in each `gap_inputs/`) | pipeline run | prompted run |
|---|---|---|---|
| 1. retrieved papers + metadata | `item1_ranked_papers.csv` | 297 ranked | 76 ranked |
| 1. selected subset | `item1_selected_papers.csv` | 60 | 60 |
| 2. post-MVFA evidence | `item2_post_mvfa_evidence.md`, `item2_post_mvfa_manifest.csv`, `item2_fulltext_fetch_manifest.csv` | 5 of the 9 checklist papers present | 1 of the 9 present |
| 3. review + key | `item3_lit_review.md`, `item3_citation_key.csv` | 52 of 60 refs cited | 60 of 60 refs cited |
| 4. anchor overlap | `item4_anchor_overlap.md`, `item4_anchor_related_titles.txt`, `item4_anchor_references.csv`, `item4_never_discussed.csv` | F1 0.1094 (7/68) | F1 0.5469 (35/68) |
| 5. topic string | `item5_topic.txt` | — | — |

`item4_*` is parsed straight from `2403.12570v1.pdf` by the pipeline's own
matcher (`qual_sg/bib_eval.py`, threshold 0.8): 68 bibliography entries. The
prompted number is computed with that same matcher; the pipeline number
reproduces `qual_sg/intermediates/bib_overlap_v4.json` exactly.

Two known data-quality points, both surfaced in the bundles rather than hidden:
the prompted run never stored publisher abstracts (only one-line agent
summaries — check `abstract_source` per row), and `prompted/survey.md` writes its
34th reference as `34:` instead of `34.`.

## ⚠️ One mismatch to know about

In the repository root, `literature_review_2page.md` / `.tex` are the
**prompt-driven** survey (K = 60), while `literature_review_2page.json` next to
them is still the **pipeline's v1 bundle** (older topic, 30 refs). The `.md`/`.tex`
and that `.json` do not describe the same thing. The prompt-driven structured data
is `Prompted_ref.json` + `prompted_reranking.csv`.

Everything about how the pipeline produced its numbers —
every intermediate result, deviation and trade-off — is in
`IMPLEMENTATION_NOTES.md` (§7 v2, §8 v3, §9 v4).
